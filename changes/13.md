# agent-spend-cap: change #13, move to the app layout

> Change: yangxdev/greenlight#13 · Product: yangxdev/greenlight#3 · Spec it changes: blueprint.md

## Change

- The one screen becomes an `app` layout: `AppShell` + `AppHeader` (no tabs) + `AppFooter`. The hero ("Know the worst case before the agents *start*.") and the numbered `Section`s 01/02/03 with rail labels go. The form is the first thing under the bar.
- One `ViewHeader`: title "Estimate"; meta line "Worst case $X if every agent retries" once the inputs are valid, otherwise "Fill in the inputs, or try the example."; **Copy link** as the one primary action and **Example run** (ghost) beside it. The "Copied" / "Link copied" / clipboard-fallback confirmation is shown next to these buttons, in a single `role="status"` region, so it is visible wherever the person is on the page.
- The working view (`px-edge py-6`) is a grid of four `Pane`s, in this order in the DOM so a phone stacks them the same way: **Inputs** (the seven estimate fields), **Estimate** (typical, worst case, reported fan-out, the two notes, the "No estimate yet" empty state), **Cap config** (tool picker, "Spend cap (USD)" field, config text, unchecked-example note, **Copy config** as a ghost button, the "Nothing to generate yet" empty state) and **Limits** (the existing five-row list). From `lg` up Inputs sits in the left column spanning two rows, Estimate and Cap config stack in the right column, Limits spans the full width below.
- `AppFooter` carries the two existing notes ("Nothing leaves your browser. The only thing stored is your theme choice.", "It estimates and writes text. It cannot stop a run.") and a "Suggest a change" link.
- Stays exactly as it is: the maths and every result, the query string and its parameter names, the empty form (only Example run fills numbers), field labels, hints and validation messages, the tools and their templates, the "unchecked examples" labelling, the copy confirmations, `GET /api/health`, light/dark theme, 320px without horizontal scroll.

## Identity

- **Layout:** `app`
- **Tag:** `agent run budgets` (unchanged)
- **Description:** unchanged
- **Screens:** `estimate · "Estimate"`
- The Headline and Sections lines of blueprint.md no longer apply. `src/app/site.ts` stays as it is.

## Data model

No change. State is still the raw-string `estimate` slice and the query string (`ip`, `op`, `it`, `ot`, `t`, `a`, `r`, `cap`, `tool`); links shared before this change open the same estimate because `useUrlSync` and the codec are not touched.

## Acceptance criteria

- **CH1:** Given no inputs, when `App` renders, then `h1` is "Estimate", there is no "Know the worst case…" text and no "01"/"02"/"03" index, the Inputs, Estimate, Cap config and Limits panes are present as regions named by their labels, "Example run" and "Copy link" buttons are present, and "No estimate yet" and "Nothing to generate yet" are shown.
- **CH2:** Given no inputs, then the meta line reads "Fill in the inputs, or try the example." and Copy link is disabled; when Example run is clicked, then the meta line shows the worst case as `Worst case $33.00 if every agent retries` (the example's figure), the Estimate pane shows Typical, Worst case and "Reported fan-out: 826 agents, worst case", and Copy link is enabled.
- **CH3:** Given the page opened with `?ip=3&op=15&it=1000&ot=500&t=10&a=2&r=1`, when it renders, then the fields show 3, 15, 1000, 500, 10, 2, 1, the typical figure is `$0.21` and the worst-case figure is `$0.42` without any click, and when the user changes Turns per agent to 25, then `location.search` contains `t=25` and the other keys keep their values.
- **CH4:** Given the example run, when the user picks each of "claude code", "codex" and "generic", then the config text changes and the "Unchecked example" note is shown each time; and when the spend cap is empty the config contains `33.00`, and after typing 5 into "Spend cap (USD)" it contains `5.00`.
- **CH5:** Given the example run and `navigator.clipboard.writeText` mocked, when "Copy config" is clicked, then it is called once with the exact text of the config and the single `role="status"` region reads "Copied"; and when "Copy link" is clicked, then it is called with `window.location.href` and the status reads "Link copied"; and with the clipboard unavailable, clicking "Copy config" makes the status read the existing "Clipboard unavailable…" message.
- **CH6:** Given an invalid value ("abc") typed into Input price, then a `role="alert"` shows the existing "Enter a number from 0 to 1,000,000." message, and the Estimate pane still shows "No estimate yet".
- **CH7:** Given the Limits pane, then it lists exactly the five existing rows (Tokens per turn, Discounts, Retries, Enforcement, Prices) with their current text.
- **CH8:** Given `App`, then the footer contains both notes verbatim and a link "Suggest a change" whose `href` ends in `/agent-spend-cap/issues/new`; and the theme switch is still present in the bar.
- **CH9 (must not break):** Given `GET /api/health` through `worker.fetch`, then it returns `{ ok: true }` with status 200; and given the unchanged `estimate.test.ts`, `url.test.ts`, `estimateSlice.test.ts`, `render.test.ts`, `healthSlice.test.ts`, `worker.test.ts` and `ui.test.tsx`, then they pass without edits.
